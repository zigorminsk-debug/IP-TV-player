# 04 — Как выпустить версию (release)

Релиз полностью автоматизирован. От вас требуется только **тег**.

## Процедура

1. Убедитесь, что изменения смержены в `main` (или собирайте прямо из ветки —
   это тоже работает).
2. Обновите `CHANGELOG.md` (секция новой версии).
3. Поставьте аннотированный тег в формате **`vX.Y.Z`** (семвер):

   ```bash
   git tag -a v1.1.0 -m "Что нового:
   - Новая функция A
   - Исправление B"
   git push origin v1.1.0
   ```

4. GitHub Actions соберёт релиз (см. [03-CI-CD.md](03-CI-CD.md)) и создаст
   **GitHub Release** с файлами:
   - `IP-TV-Player_X.Y.Z_build<N>_release.apk` — подписанный APK;
   - `IP-TV-Player_X.Y.Z_build<N>_release.aab` — бандл;
   - `app-update.json` — манифест для самообновления;
   - `SHA256SUMS.txt` — контрольные суммы.
5. Текст тега попадает в `releaseNotes` манифеста (его увидят пользователи в
   диалоге обновления). GitHub дополнительно сгенерирует release notes из
   коммитов и PR.
6. Как только Release опубликован, все установленные приложения при очередном
   запуске (или по кнопке «Проверить обновления») увидят новую версию и
   предложат установить её поверх — см. [05-AUTO-UPDATE.md](05-AUTO-UPDATE.md).

## Правила версионирования

| Ситуация | Версия |
|---|---|
| Обычный релиз | `vX.Y.Z` — увеличивайте `Z` (исправления) или `Y` (функции), `X` — ломающие изменения |
| Пробная сборка без релиза | `workflow_dispatch` с полем «version name», или обычный push → `1.0.0-dev` + номер сборки |
| Номер сборки | присваивается автоматически = `run_number` (см. [03-CI-CD.md](03-CI-CD.md)), вручную не задаётся |

**`versionCode` может только расти** — это критерий обновления в приложении.
Никогда не выпускайте версию с меньшим номером сборки, чем предыдущий релиз.

## Отмена / правка релиза

```bash
# удалить тег и релиз, пересоздать заново
git tag -d v1.1.0 && git push origin :refs/tags/v1.1.0
gh release delete v1.1.0 --yes
# …исправить, снова поставить тег (номер сборки будет уже новый)
```

## Чек-лист перед релизом

- [ ] `CHANGELOG.md` обновлён.
- [ ] Юнит-тесты зелёные (последний CI-запуск ветки прошёл).
- [ ] Версия в теге совпадает с записью в changelog.
- [ ] (Опционально) проверен APK из артефактов CI на реальном устройстве.
