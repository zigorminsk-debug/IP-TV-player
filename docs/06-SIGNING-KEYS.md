# 06 — Ключ подписи (release signing key)

## Текущая схема

| Файл | Описание |
|---|---|
| [`keystore/release-signing.p12`](../keystore/) | PKCS#12 (legacy-шифрование) с RSA-4096 ключом, сертификат действителен до **2126 года** |
| [`keystore/keystore.properties`](../keystore/keystore.properties) | Путь, тип, пароли, алиас (`iptvplayer`) |
| `scripts/generate_keystore.sh` | Скрипт генерации нового ключа |

Ключ **коммитится в репозиторий** — это осознанное решение:

- GitHub Actions всегда подписывает релизы одним и тем же ключом → APK
  устанавливаются поверх предыдущих версий, обновления работают у всех;
- любой, кто продолжит работу над проектом, сможет собирать совместимые
  обновления без «магии» с секретами;
- у владельца репозитория нет риска потерять ключ (он всегда в git-истории и в
  локальных клонах).

**Приоритет при сборке** (см. `app/build.gradle.kts` и
[03-CI-CD.md](03-CI-CD.md)): секреты репозитория → коммит-ключ → debug-ключ.

## Риски и как их снизить

⚠️ Поскольку репозиторий **публичный**, ключ знают все. Что это значит:

- Любой может подписать своим APK-«обновлением» этот же applicationId. Но
  установить его можно только вручную (sideload) — приложение само качает APK
  исключительно из GitHub Releases этого репозитория и проверяет SHA-256 из
  манифеста. Официальный канал обновлений подменить ключом нельзя — можно
  только уговорить пользователя установить сторонний APK вручную (стандартный
  риск любого sideload-приложения).
- Управлять официальными релизами могут только те, у кого есть push-доступ к
  репозиторию.

**Рекомендация для чувствительных сценариев**: переведите подписание на секреты
(команды в [03-CI-CD.md](03-CI-CD.md#перевод-подписи-на-секреты-рекомендуется-для-приватных-форков))
и удалите `keystore/` из репозитория. Подпись при этом не сменится — обновления
продолжат становиться поверх.

## ⛔ Потеря ключа = конец цепочки обновлений

Если ключ утерян и его нет в git-истории:

- новое приложение нельзя будет установить поверх старого (другая подпись);
- всем пользователям придётся удалять приложение и ставить заново (плейлисты
  и настройки будут потеряны — напомните про «Экспорт настроек»).

Поэтому:

1. **Сделайте бэкап** `keystore/release-signing.p12` и пароля в надёжное место
   (менеджер паролей, зашифрованный архив). Файл — это всё, что нужно.
2. Не переписывайте git-историю с удалением ключа.

## Ротация ключа (сознательная смена подписи)

```bash
# 1. Сгенерировать новый ключ
./scripts/generate_keystore.sh          # создаст keystore/release-signing.p12 + properties

# 2. Закоммитить и выпустить версию с повышенным versionCode (см. docs/04-RELEASE.md)
# 3. Сообщить пользователям: обновиться нужно через удаление+установку
```

Или перевести на секреты и удалить ключ из репозитория (подпись сохранится).

## Технические детали

- Формат: PKCS#12 (`-legacy`, алгоритмы 3DES/RC2) — читается всеми актуальными
  JDK и `apksigner` без дополнительных флагов.
- `storePassword == keyPassword` (ограничение формата PKCS#12 в Java).
- APK подписывается через Gradle `signingConfig` (v1+v2+v3 схемы — по умолчанию
  AGP). CI дополнительно проверяет подпись `apksigner verify`.
- ADB-проверка сертификата установленного приложения:
  `adb shell dumpsys package com.iptvplayer.app | grep -A2 signatures`
